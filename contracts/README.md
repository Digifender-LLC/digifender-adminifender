# Shared contracts

Versioned JSON Schemas (draft 2020-12) and synthetic fixtures shared by the Worker and, later, the Android app. The [LLD](../docs/specifications/lld.md) is the source for every shape here.

- `schema/v1/` — one schema per contract; `common.schema.json` holds shared definitions.
- `fixtures/v1/<schema>/valid|invalid/` — each valid fixture must pass and each invalid fixture must fail its schema.

`npm test` in `backend/` checks every fixture against its schema, and runs the Worker's own parsers against the same fixtures where a parser exists. Fixtures are synthetic; never add real mail, tokens or report payloads.

Status: **locally verified** for the schemas present. The Android JVM tests parse `fixtures/v1/sync-changes/` and `fixtures/v1/briefing/` with the app's DTOs, and Worker tests check that live sync projections and the live briefing carry the same fields.

The chat wire shapes (`chat-thread`, `chat-turn`, `chat-history`, `chat-answer`) are shared the same way: the Worker's tests compare live responses with the valid fixtures' fields, and the Android JVM tests (`ChatWireFixturesTest`) account for every valid and invalid fixture. `chat-turn` is the answer's wire shape for the phone: it carries the answer, claims, gaps, proposals and the evidence provenance `context` (every email the model was given and the privacy each had; `null` when there is no answer to show), plus the `withheld` and `invalidated` flags. `chat-answer` is the validated model output and has no `context`. `chat-history` carries `nextBefore`, the Worker's cursor for the next earlier page (null exactly when `hasMore` is false); its invalid fixtures cover the contradictory combinations. Status: **locally verified**. The whole Worker suite passed (25 files, 368 tests) and the Android JVM tests, including `ChatWireFixturesTest`, passed on the pinned toolchain (262 tests; see [slice 14h evidence](../docs/evidence/slice-14h.md)).

The reviewed-action and export wire shapes are shared too: `review-request`, `review-prepared`, `review-readback`, `review-confirmed`, `operation`, `export-scope`, `export-request` and `export-status`. `review-readback` is the content-free recovery state behind GET `/reviews/{id}`, and `operation` carries the `cleanup` status of an archive deletion; both state what they do not prove in their descriptions. Worker tests compile every schema in Node into Ajv standalone validators (`vitest.config.ts`, served as `virtual:contract-validators`, because the Workers runtime cannot compile schemas), check the Worker's real responses against them, run every fixture through the same validators inside the Workers runtime, and check that the Worker's request validators accept and refuse the request fixtures exactly as the schemas do. `export-status.invalidatedReason` also has `admission_changed` (a quarantine-only export whose source was released); the `operation.cleanup` `unrecorded` count includes sources whose ledger row contradicts their finished cleanup job. Status: **locally verified** on the Worker side (see the [slice 14i backend evidence](../docs/evidence/slice-14i-backend.md)) and, since the Android part of 14i, by strict hand-written parsers in `android/core/data` (`StrictWire.kt`, `ReviewApi.kt`, `ExportApi.kt`) whose JVM test `ReviewExportWireFixturesTest` parses every valid fixture of these eight contracts and requires every invalid one to be refused, and fails if a fixture is added without being accounted for (see the [slice 14i Android evidence](../docs/evidence/slice-14i-android.md)).

The device extraction wire shapes are shared as well: `extraction-claim-request`, `extraction-claim`, `extraction-batch`, `extraction-batch-result` and `extraction-outcome` (the heartbeat body, the heartbeat answer and the outcome answer are small and have no schema yet). The schemas state the rules between fields with if/then/else: a batch carries `manifestHash` exactly when it is `complete`, `totalPages` only then, and a result carries `attachment` exactly when it published. Worker tests compile the schemas into the validators of the Workers runtime, check that the Worker's real requests and answers satisfy them, and check that the Worker's request validators accept and refuse the request fixtures exactly as the schemas do. Rules the schemas cannot state (the checkpoint, page order, the 128 KiB total, `batchHashes` having one entry per `nextBatchOrdinal`) are enforced by the Worker and covered by its tests. Status: **locally verified** on the Worker side (see the [slice 14j backend evidence](../docs/evidence/slice-14j-backend.md)) and by strict hand-written parsers in `android/core/data` (`ExtractionApi.kt`) whose JVM test `ExtractionWireFixturesTest` parses every valid fixture of these five contracts, requires every invalid one to be refused, and fails if a fixture is added without being accounted for (see the [slice 14j Android evidence](../docs/evidence/slice-14j-android.md)).

The device-work inference shapes are shared too: `device-work-readiness`, `device-work-claim`, `device-work-result`, `device-work-result-answer` and `device-work-decline`. A triage task carries its email and revision and no turn; a chat task carries its turn and no email (stated with if/then in the claim). The Worker's inference and chat tests check every claim, result and decline it accepts or answers against them, and the Android parsers account for every fixture (`DeviceWorkWireFixturesTest`); the heartbeat and its answer have no schema. Status: **locally verified** on both sides (see the [local inference client evidence](../docs/evidence/local-inference-client.md)).
