# Implementation roadmap

Tracks delivery of the [baseline phases](specifications/baseline.md#delivery-phases) in small reviewable slices. Status words follow [AGENTS.md](../AGENTS.md): **planned**, **implemented**, **locally verified**, **staging verified**, **production accepted**. Nothing below is deployed, and no slice is staging verified or production accepted.

| 14. Android app: Gradle toolchain, Room, sync, Compose screens | FR-002, FR-010, FR-023, AT-10, AT-15 | In progress: 14a–14f locally verified; 14g–14i JVM/lint/debug/unsigned-release verified; instrumentation pending; 14j partial | 14a: Gradle 9.8.0 wrapper with checksum, JDK 21, AGP 9.4.1, Kotlin 2.4.20, Compose BOM 2026.09.00, compile SDK 37, min SDK 31 (`android/gradle/libs.versions.toml`). `:core:model` JVM tests cover the concern controls (same table as the backend), optimistic edits that keep the server revision, outbox decisions (same idempotency key on resend, stale revision becomes a conflict, never an overwrite) and opaque push payload parsing. The app shell compiles, passes Lint with warnings as errors and builds an unsigned release. 14b: Room schema v1 (concerns, sources, pending mutations, sync state) and an OkHttp client with bounded responses. The sync engine sends queued edits first, in per-concern order with predicted revisions and a fixed idempotency key on every resend. It then pulls feed pages that commit together with their cursor; an expired cursor rebootstraps and keeps queued edits. Stale edits become conflicts that block later edits until the owner reapplies or discards them, and an expired session holds the queue. JVM tests use fakes, MockWebServer and the shared `sync-changes` contract fixture. Room store tests are compiled but need an emulator. 14c: a session layer for passkey sign-in (Credential Manager 1.6.0, no allowCredentials) and recent-auth confirmation. Tokens are sealed with a non-exportable Android Keystore AES-GCM key in no-backup storage. Access tokens are refreshed one at a time, and a refresh that has started is never cancelled, so a rotated refresh token is never replayed. A refused refresh requires sign-in again; an unanswered one keeps the token for later. A 401 marks only the refused token stale, and sign-out forgets tokens before revoking the family on the server. JVM tests cover the session rules and the `/auth` wire format; the Keystore vault test is compiled but needs an emulator. 14d: Compose sign-in, inbox, concern detail and settings screens backed by Room through `ConcernRepository` and view models. Queued edits show on top of the server copy and are marked unsent; conflicts and refused edits are listed first and only the owner reapplies or drops them. Controls are checked against what the owner sees. Freshness never claims a sync that did not happen, and cached items stay readable when the session needs a new sign-in. WorkManager runs periodic and on-demand sync under unique names. Sign-out names unsent edits, cancels sync and clears the cache. JVM tests cover the overlay, ordering, repository and a view model. 14e: FCM receiver and three notification channels (critical, review reminders, processing). A push is validated with the shared parser, shown with generic text, opens only a checked concern ID or the briefing, and triggers a sync; it never changes local state. A signed-out phone shows nothing. The Worker now sends data-only FCM messages, so the app draws the notification on the right channel, and it skips devices with no live session. Token and permission registration runs in WorkManager with a fixed idempotency key per attempt and a digest to skip repeats; Settings shows and requests the notification permission. Firebase config (`app/google-services.json`) is not committed. Without it, the build reports push as not set up. 14f: an Archive tab with archive and quarantine views listed from the synced Room cache, exact search over `GET /search` (sender and received-date filters, further pages through the cursor) and source detail over `GET /sources/{id}` and `/sources/{id}/chunks` with body text, attachment inventory and linked items. The concern screen lists its source emails. Search results always state their coverage: complete, partial while more archive partitions remain (order not final), or cached-only when offline, signed out or the server fails; cached-only search matches subjects, senders and the text of opened sources with literal, bound LIKE terms. Opened text is kept in a new Room table (schema v2, auto-migration from v1) only while the synced source has the same revision; sync prunes it in the same transaction as a deletion or change, a late response cannot bring deleted text back, and a deleted source disappears from an open screen. Bodies over 1,000,000 characters are kept in part and marked. JVM tests cover the repository, wire format and view models; the Room cache and migration tests are compiled but need an emulator. Remaining slices are listed under [Next steps](#next-steps). No emulator, device, live FCM or live passkey evidence yet; screens have not been checked with screenshots or TalkBack. |
