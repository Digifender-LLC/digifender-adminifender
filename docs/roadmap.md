# Implementation roadmap

Tracks delivery of the [baseline phases](specifications/baseline.md#delivery-phases) in small reviewable slices. Status words follow [AGENTS.md](../AGENTS.md): **planned**, **implemented**, **locally verified**, **staging verified**, **production accepted**. Nothing below is deployed, and no slice is staging verified or production accepted.

| 8. Actions follow the state diagram with independent read/acknowledged/resolved fields, undo only at the exact resulting revision within 10 minutes, snooze expiry, corrections with rule preview only, merge/split preserving links and events, and briefings across two reviews. Every concern write lands with its event, change and review time in one assertion-guarded batch. The 200-message AT-05 corpus and recall gates wait for inference; reverse-order replies need a manual merge. |
| 9. | 10. Exports at a change-sequence snapshot: JSONL records, original MIME and attachments, SHA-256 manifest with omissions, invalidation on deletion, 7-day expiry. Exports run as one job without ZIP64, so very large archives need a later resumable export; restore and backup belong to slice 15. |
| 11. Inference routing, budgets and cloud adapter | FR-021, FR-022, FR-024, AT-07 (server side) | Locally verified with a fake Workers AI binding; no real model, account or phone yet | `npm run check`: deterministic routing (no-AI and restricted blocked, quarantine and deletion blocked, local-only waits, a fresh charging phone with battery >= 30 % and below severe thermal wins, else cloud, else queued with the reason). Cloud is denied when the binding, model rate or account attestation is missing. Guarded day/month counters with concurrency 1 (two concurrent reservations, one wins), automatic allowance, included allocation before an owner-set paid ceiling, expiry release. `dispatched_at` before I/O; provider errors, timeouts and interrupted runs become uncertain, keep exposure and need owner reconciliation. Output validated against `triage-output.schema.json` (parity test over the shared fixtures) plus evidence offsets and catalog services; one separately reserved repair, then visible failure. Device claim, heartbeat and result with lease fencing, late and duplicate results refused, one success per job. Not covered: real Workers AI calls and pricing, provider headroom readback, the Android worker (slice 14), applying model output to concerns and briefing summaries. |
| 12. Grounded chat | FR-025 to FR-028, AT-08 (server side) | Locally verified with a fake Workers AI binding | `npm run check`: global, source, concern and service scopes; quarantined scopes refused. Retrieval is scope-intersected and post-filtered: quarantined, deleted and no-AI sources never reach a model, and at most 4 excerpts are sent. Turn ID as request identity, with recovery that never redispatches and a conflict on changed content. The answer is persisted together with completion. Fabricated or out-of-range citations and unsupported or tool-call output are rejected, with one repair and then a visible failure. Evidence claims must cite. Prompt-injection fixture text stays data. A provider failure leaves the turn uncertain with no replay. Only undispatched turns can be cancelled. Local-only evidence waits for a foreground phone and is accepted under its lease. Deletion removes stored answers, and later quarantine withholds them. Not covered: model tool iterations (`search_sources` and the others), semantic candidates (P3), real model quality, reviews for `email.reply` proposals, and the Android chat UI (slice 14). |
| 13. Notifications and diagnostics | FR-029 to FR-032, AT-09 | Locally verified with a fake push adapter | `npm run check`: rule-critical events, one per material signal, that bypass quiet hours, with no new signal for mark-read, acknowledge or snooze and no critical push for owner corrections. Due reminders once per due revision, deferred past quiet hours (DST cases in pure tests) and superseded by a new date. Inactivity reminders only with eligible backlog: not for empty, routine-only or snoozed-only backlog, not reset by sync, once per cooldown and dropped after a meaningful review. Opaque payloads with generic text. Denied permission, missing adapter, invalid and rotated tokens, lost responses and interrupted sends stay uncertain and are never resent. Encrypted token storage, device-bound registration and FCM v1 request and response mapping against a fake fetch. Private health reports each pipeline component separately, with unobserved, unavailable and stale states distinct from success, and a content-free diagnostics export. Not covered: live FCM delivery, Doze and the Android receiver and health screen (slice 14), and provider headroom readback. |
| 14. Android app: Gradle toolchain, Room, sync, Compose screens | FR-002, FR-010, FR-023, AT-10, AT-15 | In progress: toolchain, domain, sync, session and first screens locally verified (JVM and Lint) | 14a: Gradle 9.8.0 wrapper with checksum, JDK 21, AGP 9.4.1, Kotlin 2.4.20, Compose BOM 2026.09.00, compile SDK 37, min SDK 31 (`android/gradle/libs.versions.toml`). `:core:model` JVM tests cover the concern controls (same table as the backend), optimistic edits that keep the server revision, outbox decisions (same idempotency key on resend, stale revision becomes a conflict, never an overwrite) and opaque push payload parsing. The app shell compiles, passes Lint with warnings as errors and builds an unsigned release. 14b: Room schema v1 (concerns, sources, pending mutations, sync state) and an OkHttp client with bounded responses. The sync engine sends queued edits first, in per-concern order with predicted revisions and a fixed idempotency key on every resend. It then pulls feed pages that commit together with their cursor; an expired cursor rebootstraps and keeps queued edits. Stale edits become conflicts that block later edits until the owner reapplies or discards them, and an expired session holds the queue. JVM tests use fakes, MockWebServer and the shared `sync-changes` contract fixture. Room store tests are compiled but need an emulator. 14c: a session layer for passkey sign-in (Credential Manager 1.6.0, no allowCredentials) and recent-auth confirmation. Tokens are sealed with a non-exportable Android Keystore AES-GCM key in no-backup storage. Access tokens are refreshed one at a time, and a refresh that has started is never cancelled, so a rotated refresh token is never replayed. A refused refresh requires sign-in again; an unanswered one keeps the token for later. A 401 marks only the refused token stale, and sign-out forgets tokens before revoking the family on the server. JVM tests cover the session rules and the `/auth` wire format; the Keystore vault test is compiled but needs an emulator. 14d: Compose sign-in, inbox, concern detail and settings screens backed by Room through `ConcernRepository` and view models. Queued edits show on top of the server copy and are marked unsent; conflicts and refused edits are listed first and only the owner reapplies or drops them. Controls are checked against what the owner sees. Freshness never claims a sync that did not happen, and cached items stay readable when the session needs a new sign-in. WorkManager runs periodic and on-demand sync under unique names. Sign-out names unsent edits, cancels sync and clears the cache. JVM tests cover the overlay, ordering, repository and a view model. Next: archive and chat screens, wait and due-date forms, push receiver, local inference. No emulator, device or live passkey evidence yet; screens have not been checked with screenshots or TalkBack. |
