# Implementation roadmap

Tracks delivery of the [baseline phases](specifications/baseline.md#delivery-phases) in small reviewable slices. Status words follow [AGENTS.md](../AGENTS.md): **planned**, **implemented**, **locally verified**, **staging verified**, **production accepted**. Nothing below is deployed, and no slice is staging verified or production accepted.

"Edit as a new question" moves the exact text into the draft and removes the question in one transaction, only when the draft is empty; otherwise the question stays. Every Worker read is stored in Room before the screen shows it, under a sign-out generation and per-item ticket, finished turns never go back to waiting, and a response for a conversation that sign-out or deletion removed stores nothing. Privacy (FR-022, AT-17) rests on exact provenance, not timestamps: the Worker now records, with each answer, every email the model was given and the privacy each had (`citations_json.context`), re-judges all of them on every read (ready, admitted, model-eligible, no stricter than when used; cited passages readable; proposal targets and cited emails inside the context; unknown provenance fails closed) and returns that list as `context` with the answer. The phone checks the same list on every merge and stores it with the answer; a synced deletion, quarantine, state change or stricter policy on any email in it removes the stored answer for good in the same transaction as the sync write, whether or not it was cited, and nothing else is touched (questions never sent or still in flight, answers about other emails, unrelated mail arriving at any time). An answer is shown only when all its emails are on the phone, eligible and not stricter than recorded; otherwise it is held back and decided again on the next read. Missing context (an older Worker) is held back, not believed; an answer that breaks the answer contract (evidence or report claim with no citation, unsupported suggestion kind, target or citation outside the context) is rejected and never stored. Shared synthetic fixtures `chat-thread`, `chat-turn` (which carries the answer, its provenance `context` and the withheld and invalidated flags), `chat-history` and `chat-answer` (the validated model output, without `context`) define the wire shapes for the Worker's tests and the phone's.
