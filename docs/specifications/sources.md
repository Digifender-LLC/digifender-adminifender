# Verified technical sources

Checked October 1, 2026. These are primary documentation or upstream package sources inspected while preparing the specification. A documented API or price is not evidence that this account is configured, that a model works acceptably on the owner's Galaxy S24+, or that a deployed integration has passed acceptance. Prices are USD before tax. Recheck changing limits, package compatibility, model availability and prices when freezing an implementation release.

The [technical design](tdd.md) distinguishes provider facts from selected application limits. The [research notes](../feature-suggestions.md) retain local Whumpo evidence and its implementation boundaries. Citation IDs below are stable; additions receive new IDs.

## Cloudflare

| ID | Inspected source | Supported claim and boundary |
| --- | --- | --- |
| <a id="cf-01"></a>CF-01 | [Email Routing setup](https://developers.cloudflare.com/email-service/get-started/route-emails/) | Native inbound routing uses a configured domain, mail DNS and address rules. Existing mailbox setup must be inspected before changing DNS. |
| <a id="cf-02"></a>CF-02 | [Email Worker API](https://developers.cloudflare.com/email-service/api/route-emails/email-handler/) | Worker receives envelope addresses, headers, raw MIME stream and size; `setReject()` is permanent rejection. This is not a documented API for requesting a transient SMTP retry. |
| <a id="cf-03"></a>CF-03 | [Spam filtering example](https://developers.cloudflare.com/email-service/examples/email-routing/spam-filtering/) | Worker-side sender/subject checks and rejection are supported. Example heuristics are illustrative, not a managed spam classifier or an accuracy guarantee. |
| <a id="cf-04"></a>CF-04 | [Email Service limits](https://developers.cloudflare.com/email-service/platform/limits/) | Inbound Routing rejects messages above 25 MiB. Outbound limits differ; the inbound ceiling is not a promise that every MIME structure can be parsed within Worker resources. |
| <a id="cf-05"></a>CF-05 | [Email Service pricing](https://developers.cloudflare.com/email-service/platform/pricing/) | Routing has no separate inbound-message quota charge; Worker execution is separately priced. Arbitrary outbound sending requires paid Workers and domain onboarding. Published outbound allowance is 3,000/month then $0.35/1,000. |
| <a id="cf-06"></a>CF-06 | [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) | Paid account minimum $5/month; 10 million requests and 30 million CPU milliseconds included, then $0.30/million requests and $0.02/million CPU milliseconds. Account allowances are not private to this app. |
| <a id="cf-07"></a>CF-07 | [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) | Worker isolate memory is 128 MB on both plans. Paid HTTP CPU defaults to 30 seconds; frequent Cron CPU is bounded. Streaming and short jobs are necessary. |
| <a id="cf-08"></a>CF-08 | [D1 SQL statements](https://developers.cloudflare.com/d1/sql-api/sql-statements/) | D1 documents FTS5, including `fts5vocab`, and SQLite-compatible SQL with explicit limitations. |
| <a id="cf-09"></a>CF-09 | [D1 database methods](https://developers.cloudflare.com/d1/worker-api/d1-database/) | Prepared statements and `batch()` are available; a failing batch statement rolls back its batch. Read sessions provide consistency controls; no transaction extends into R2 or Queues. |
| <a id="cf-10"></a>CF-10 | [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) | Paid per-database ceiling 10 GB; row/string/BLOB maximum 2,000,000 bytes; 100 bound parameters per query. Free per-database capacity is 500 MB. Index growth must be monitored. |
| <a id="cf-11"></a>CF-11 | [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) | Paid monthly included use: 25 billion read rows, 50 million written rows, 5 GB storage; overages $0.001/million reads, $1/million writes and $0.75/GB-month. Indexes contribute to writes and storage. |
| <a id="cf-12"></a>CF-12 | [D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/) | Versioned SQL migrations are applied through Wrangler. A migration framework is not a substitute for a tested forward/restore procedure. |
| <a id="cf-13"></a>CF-13 | [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) | Paid restore history spans 30 days; Free spans seven. Time Travel covers D1 rather than attachment objects or external side effects. |
| <a id="cf-14"></a>CF-14 | [R2 pricing](https://developers.cloudflare.com/r2/pricing/) | Standard: $0.015/GB-month, $4.50/million Class A and $0.36/million Class B operations; included 10 GB-month, 1 million A and 10 million B. Published billing units round up. Internet egress has no R2 charge. |
| <a id="cf-15"></a>CF-15 | [Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/) | Paid includes 1 million operations/month, then $0.40/million. A small successful delivery normally incurs write, read and delete; retries add operations. |
| <a id="cf-16"></a>CF-16 | [Queues delivery guarantees](https://developers.cloudflare.com/queues/reference/delivery-guarantees/) | At-least-once delivery requires consumer deduplication. It does not make external operations exactly once. |
| <a id="cf-17"></a>CF-17 | [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) | 10,000 neurons/day included; overage $0.011/1,000 neurons. Llama 3.2 3B table rates: $0.051/million input and $0.335/million output tokens; 4,625 and 30,475 neurons/million respectively. BGE small: 1,841 neurons/million input. |
| <a id="cf-18"></a>CF-18 | [Llama 3.2 3B model](https://developers.cloudflare.com/workers-ai/models/llama-3.2-3b-instruct/) | Selected cloud text model ID is `@cf/meta/llama-3.2-3b-instruct`; the binding supports message input. Model card displays $0.0509/million input, a rounding difference from the pricing table used for estimates. |
| <a id="cf-19"></a>CF-19 | [BGE small model](https://developers.cloudflare.com/workers-ai/models/bge-small-en-v1.5/) | Selected P3 embedding model outputs 384 dimensions and accepts at most 512 tokens. Embedding chunks must respect this separately from inference chunks. |
| <a id="cf-20"></a>CF-20 | [Vectorize pricing](https://developers.cloudflare.com/vectorize/platform/pricing/) | Paid includes 50 million queried dimensions/month and 10 million stored dimensions. Published overages are $0.01/million queried and $0.05/100 million stored dimensions. Recompute using the provider's dimension accounting at P3 activation. |
| <a id="cf-21"></a>CF-21 | [Workers Vitest integration](https://developers.cloudflare.com/workers/testing/vitest-integration/) | Current `@cloudflare/vitest-plugin` executes tests in the Workers runtime with local bindings; the older pool package has a migration guide. Remote email delivery still needs deployed tests. |
| <a id="cf-22"></a>CF-22 | [Compatibility dates](https://developers.cloudflare.com/workers/configuration/compatibility-dates/) | Compatibility date controls runtime behavior and belongs in the versioned deployment configuration. Upgrade it with tests rather than automatically. |
| <a id="cf-23"></a>CF-23 | [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/) (page updated 2026-10-01, read 2026-10-04) | `@cf/meta/llama-4-scout-17b-16e-instruct`: $0.270/million input and $0.850/million output tokens; 24,545 and 77,273 neurons/million. Staging probes on 2026-10-04 with synthetic mail: Llama 4 Scout and Llama 3.3 70B returned valid JSON with every quote found for chat and triage; Llama 3.2 3B returned zero offsets and malformed repair JSON; Mistral Small 3.1 wrapped JSON in code fences. |

## Android, local inference and push

| ID | Inspected source | Supported claim and boundary |
| --- | --- | --- |
| <a id="and-01"></a>AND-01 | [Credential Manager](https://developer.android.com/identity/credential-manager) | Native credential entry point selected for passkeys. It is not the application's authorization/session store. |
| <a id="and-02"></a>AND-02 | [Credential Manager prerequisites](https://developer.android.com/identity/credential-manager/prerequisites) | Passkeys require Digital Asset Links between sign-in domain, Android package and signing certificate. Hosted JSON must be retrievable; distributed Play signing identity matters. |
| <a id="and-03"></a>AND-03 | [Offline architecture](https://developer.android.com/topic/architecture/data-layer/offline-first) | Local persistent data can drive reads while work is synchronized with the network. Offline availability depends on what has actually been cached. |
| <a id="and-04"></a>AND-04 | [Room FTS4](https://developer.android.com/reference/androidx/room/Fts4) | Room exposes FTS4 entities. Local and D1 FTS implementations differ; API-level search semantics must be tested for parity. |
| <a id="and-05"></a>AND-05 | [WorkManager persistent work](https://developer.android.com/develop/background-work/background-tasks/persistent) | Persistent jobs can survive restarts and use constraints; execution is subject to Android scheduling rather than an exact clock. |
| <a id="and-06"></a>AND-06 | [Long-running workers](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running) | Foreground workers can still consume JobScheduler quota, including Android 16 limitations. Prefer checkpointed bounded inference/OCR jobs. |
| <a id="and-07"></a>AND-07 | [ML Kit text recognition](https://developers.google.com/ml-kit/vision/text-recognition/v2/android) | Bundled `com.google.mlkit:text-recognition` supplies Latin OCR without a first-use model download. OCR accuracy depends on source quality; other scripts require separate models. |
| <a id="and-08"></a>AND-08 | [PdfRenderer.Page](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page) | Page text extraction via `getTextContents()` begins at API 35. Older supported Android versions can render pages for OCR. |
| <a id="and-09"></a>AND-09 | [Notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission) | Android 13+ requires runtime notification permission for ordinary app notifications. Permission denial cannot be treated as successful delivery. |
| <a id="and-10"></a>AND-10 | [App signing](https://developer.android.com/studio/publish/app-signing) | Play App Signing separates the upload key from the distribution signing key. Register the latter's fingerprint for deployed passkey association. |
| <a id="and-11"></a>AND-11 | [Play internal testing](https://support.google.com/googleplay/android-developer/answer/9845334?hl=en-CA) | Internal test track supports a restricted tester list and App Bundle delivery. Account setup, eligibility and actual delivery require verification. |
| <a id="ai-01"></a>AI-01 | [LiteRT-LM Android/Kotlin guide](https://developers.google.com/edge/litert-lm/android) | Maven Android adapter, engine/conversation lifecycle and coroutine streaming are documented; the guide references Gemma3-1B-IT. Load models away from the main thread. |
| <a id="ai-02"></a>AI-02 | [LiteRT-LM overview](https://developers.google.com/edge/litert-lm/overview) | Android CPU and GPU backends exist. Published benchmarks on other models/devices cannot be substituted for the owner's S24+ acceptance results. |
| <a id="ai-03"></a>AI-03 | [Gemma3-1B-IT artifact card linked by Google](https://huggingface.co/litert-community/Gemma3-1B-IT) | Model variants have different quantization/context limits; access requires model terms. Record the selected file, revision, hash, license and context capacity in the manifest. |
| <a id="ai-04"></a>AI-04 | [Google Gemma3 CPU/GPU Android sample](https://github.com/google-ai-edge/litert-samples/blob/main/samples/litert/qualcomm/gemma3/cpu_gpu/README.md) | Demonstrates an int4 `.litertlm` Gemma3-1B artifact and CPU/GPU paths. A sample is feasibility evidence, not an app-specific performance guarantee. |
| <a id="fcm-01"></a>FCM-01 | [FCM HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api) | Server sends using short-lived OAuth access tokens derived from a service account. No service-account secret belongs in the Android app. |
| <a id="fcm-02"></a>FCM-02 | [Android FCM priority](https://firebase.google.com/docs/cloud-messaging/android-message-priority) | High priority is for time-sensitive visible notifications and may be deprioritized. Delivery is not an exact alarm or proof that the owner read an item. |
| <a id="fcm-03"></a>FCM-03 | [Firebase pricing](https://firebase.google.com/pricing) | FCM is listed as no-cost. This does not make unrelated Firebase/Google Cloud services free; none are selected for app storage or inference. |

## Selected upstream libraries

| ID | Inspected source | Supported claim and boundary |
| --- | --- | --- |
| <a id="lib-01"></a>LIB-01 | [postal-mime](https://github.com/postalsys/postal-mime) | MIME parser targets browser/serverless runtimes and exposes structured messages and attachments. Resource-limit acceptance remains necessary. |
| <a id="lib-02"></a>LIB-02 | [Ajv standalone validators](https://ajv.js.org/standalone.html) | Generate validation functions at build time; do not introduce runtime dynamic code generation in the Worker. |
| <a id="lib-03"></a>LIB-03 | [parse5](https://github.com/inikulin/parse5) | HTML parsing supports an application-owned text projection; a parser alone does not implement archive normalization policy. |
| <a id="lib-04"></a>LIB-04 | [fflate](https://github.com/101arrowz/fflate) | ZIP/decompression primitives support streamed archives and DOCX reading. The application must enforce expansion and path limits. |
| <a id="lib-05"></a>LIB-05 | [fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser) | XML parser selected for DOCX text parts; disable entity expansion and reject DTDs in the application adapter. |
| <a id="lib-06"></a>LIB-06 | [SimpleWebAuthn server](https://simplewebauthn.dev/docs/packages/server) | Registration/authentication helpers and verification options support the passkey verifier. A Workers bundle/runtime smoke test is still required. |

## Evidence not established by this research

No Cloudflare/Firebase/Play account was inspected or provisioned. No domain ownership, email DNS, sending entitlement, app signing key, phone OS/SoC, model artifact download, spending ceiling, workload or inference benchmark was verified. No existing Whumpo operator API or email publisher is assumed beyond the repository evidence retained in the research notes. Deployment preflight in the [TDD](tdd.md#preflight-and-release-gates) records these inputs without replacing selected designs with undocumented alternatives.
